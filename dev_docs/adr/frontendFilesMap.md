# Карта файлов фронтенда

Next.js 16 (App Router) + React 19, TypeScript strict, Tailwind v4. Говорит только
с DRF API. Алиас `@/*` → `src/*`. Всё ниже — относительно `frontend/mentorlm/src/`.

Четыре не-UI папки разделены по тому, **что это за вещь**, а не по тому, какая
страница её использует: `content/` — тексты, `types/` — контракт с бэкендом,
`hooks/` — всё, что завязано на React, `lib/` — чистый код без React и без текстов.

## `src/content/` — все тексты интерфейса

Любая видимая пользователю строка живёт здесь, по файлу на поверхность. Строки с
подставляемым значением — функции (`upsell: (planName) => …`); заголовок с
акцентным словом хранится как `{before, accent, after}`. Компонент — разметка,
не копирайтинг. **Добавить текст = добавить его сюда.**

- **site.ts** — SEO-мета, 404, cookie-уведомление, общие подписи, ошибки сети и сессии.
- **landing.ts** — лендинг: герой, проблема, решение, возможности, шаги, соцдоказательство, тарифы, FAQ, CTA, футер.
- **blog.ts** — статьи блога данными: тип `BlogPost` + блоки `h2/h3/p/ul/ol/quote`. Новая статья = объект в массиве.
- **auth.ts** — вход, регистрация, письма (подтверждение, сброс пароля).
- **billing.ts** — тарифы, экран оформления (формулировки согласия на автосписания и акцепта оферты юридически обязательны — не сокращать), страница возврата, вкладки «Подписка» и «Платежи». Цены здесь — ЗАПАСНЫЕ, реальные приходят с бэкенда.
- **app.ts** — режимы, сценарии (подписи + иконки), сайдбар, чат, композер, меню аккаунта, баннеры.
- **settings.ts** — весь диалог настроек: вкладки, подписи и варианты опций.

**Исключение — документы.** `legal/{offer,privacy,terms}`, `about`, `contacts`
держат текст прямо в своих `page.tsx`: это сплошной текст, и нарезка на массивы
строк сделала бы правку сложнее.

## `src/types/` — контракт с бэкендом

- **app.ts** — `ModeId`, `Scenario`, `ChatPreview` и др. Строковые коды режимов и сценариев — то, что читают `apps/ai/registry.py` и `scenarios.py`. Переименовать код = сломать API; переписать подпись в `content/` — нет.
- **settings.ts** — `ModelTier`, `MemoryScope` и другие коды настроек, которые принимает `UserSettingsSerializer`. Менять только вместе с бэкендом.

## `src/hooks/` — всё, что завязано на React

- **useApi.ts** — единственный HTTP-клиент к бэку: `get/post/patch/delete` и `stream()` для SSE. Подставляет access-токен, на 401 один раз повторяет со свежим, повторяет безопасные запросы при сетевом сбое, терпит битые SSE-события. **Не** шлёт `Accept: text/event-stream` (DRF ответил бы 406).
- **useOnline.ts** — есть ли сеть: честное «нет связи» вместо непонятной ошибки отправки.
- **usePlanPrices.ts** — цены тарифов с `/api/billing/plans/`: цена живёт в одном месте (`billing/limits.py`), витрина не может разойтись со списанием.

## `src/lib/` — чистый код без React и без текстов

- **cn.ts** — склейка классов Tailwind (clsx + tailwind-merge).
- **auth-api.ts** — публичные эндпоинты без сессии (сброс пароля, подтверждение почты по токену из письма). Отдельно от `useApi`, потому что пришедший по ссылке из письма не залогинен.
- **safe-url.ts** — проверки адресов перед переходом (`?next=` и ссылки из API — чужой ввод; защита от открытого редиректа).
- **chat-cache.ts** — кэш чатов, сообщений и выбранного сценария в localStorage для мгновенного рендера; ключи по userId.
- **chat-stream.ts** — реестр «живых» ответов вне React-дерева: экран чата может размонтироваться посреди генерации (уход в другой режим, `/billing`), а ответ не должен пропасть.
- **chats.ts** — раскладка сайдбара по датам; возвращает коды групп, подписи — в `content/app.ts`.
- **composer-quote.ts** — маленькая шина «блок кода → композер»: вставить цитату выделенных строк в поле ввода.
- **download.ts** — сохранить файл с API (экспорт `.docx`/`.md`): ссылкой нельзя, нужен заголовок Authorization, поэтому запрос + objectURL.
- **draft.ts** — черновик вопроса с лендинга (sessionStorage) → подставляется в пустой чат.
- **highlighter.ts** — подсветка кода через Shiki (ленивые грамматики и темы).
- **limits.ts** — клиентские потолки длины, зеркало бэкенда: `PERSONA_LIMITS`, `MAX_MESSAGE_CHARS`, `MAX_TITLE_CHARS`, `MAX_FILES`, `MAX_FILE_MB`. Это подсказка, а не защита; менять вместе с бэкендом.
- **settings-storage.ts** — ключи localStorage настроек и их очистка при выходе (вынесено, чтобы не замкнуть импорт AuthProvider ↔ SettingsProvider).
- **brand-mark-svg.ts** — знак-линза строкой SVG для генерации иконок через next/og.

## `src/` — прочее

- **middleware.ts** — только заголовки безопасности и CSP-nonce на каждый запрос. **К авторизации отношения не имеет**: httpOnly refresh-cookie на пути `/api/auth/` ему не видна. Проверка входа — в `(modes)/layout.tsx`.

## `src/app/` — маршруты и страницы (App Router)

- **layout.tsx** — корневой layout: шрифты Manrope + JetBrains Mono (кириллица), глобальные стили, SEO, `AuthProvider`, `GlassFilters`, cookie-уведомление, анти-FOUC скрипт темы/шрифта. Читает CSP-nonce через `headers()` — поэтому все маршруты рендерятся динамически.
- **globals.css** — дизайн-система: брендовые токены, мост `@theme inline` к Tailwind, тёмная тема, стекло (`.glass*`, `.glass-chip`, `.glass-plain`, `.inset-well`), типографика, `.md` (ответы ИИ), `.doc-prose` (документы), анимации.
- **not-found.tsx** — 404 с маскотом.
- **icon.svg / apple-icon.tsx / opengraph-image.tsx** — favicon, apple-touch-icon и OG-картинка (две последние генерируются через next/og).

### `(landing)/` — маркетинговые страницы

- **layout.tsx** — навбар сверху + футер снизу.
- **page.tsx** — главная (`/`): секции лендинга по порядку.
- **about/page.tsx** — «О проекте» (`/about`), текст в `DocPage`.
- **blog/page.tsx** — листинг статей (`/blog`) из `content/blog.ts`.
- **blog/[slug]/page.tsx** — статья; маршруты и метаданные генерируются из данных.
- **contacts/page.tsx** — контакты и реквизиты.
- **legal/offer/page.tsx** — публичная оферта (раздел 7 — правила автосписаний по ФЗ-376).
- **legal/privacy/page.tsx** — политика обработки ПДн (152-ФЗ).
- **legal/terms/page.tsx** — пользовательское соглашение (раздел 9 — права на результат генерации).

### `(modes)/` — приложение (требует входа)

- **layout.tsx** — каркас приложения и **охранник маршрутов**: пока сессия `loading` — ничего, `anon` — редирект на `/sign-in?next=…`. Провайдеры `SettingsProvider` → `SubscriptionProvider` → `ConversationsProvider`, сайдбар, баннеры, меню аккаунта, диалог настроек (открывается и по `?settings=<вкладка>` из писем). **Новый защищённый режим = новый маршрут здесь.**
- **chat/page.tsx** — «Общий» (`/chat`): тонкая обёртка над `ChatScreen`.
- **code/page.tsx** — «Код» (`/code`).
- **research/page.tsx** — «Исследовать» (`/research`).

### `billing/` — оплата

- **layout.tsx** — плавающая кнопка «Назад» + `SubscriptionProvider` (странице тарифов нужен действующий план).
- **page.tsx** — тарифы (`/billing`): промо-герой и карточки планов; триала в карточках нет, но он учтён в порядке тарифов.
- **checkout/page.tsx** — оформление (`/billing/checkout?plan=`): сводка, чекбокс автопродления (снят по умолчанию — ст. 16 ЗоЗПП), акцепт оферты, предупреждение о смене тарифа, `VerifyGate` для неподтверждённой почты, переход на форму ЮKassa.
- **return/page.tsx** — возврат с формы (`/billing/return?payment=`): опрашивает статус, не дожидаясь вебхука; при отказе показывает причину от банка; объясняет, если автопродление не привязалось.

### Авторизация и письма

- **sign-in/page.tsx** — вход (`/sign-in`), почта + пароль, возврат по `?next=` (только внутренние адреса).
- **sign-up/page.tsx** — регистрация: почта, пароль с повтором, обязательное согласие на обработку ПДн.
- **forgot-password/page.tsx** — запрос письма; экран успеха уклончив («если аккаунт есть…»).
- **reset-password/page.tsx** — новый пароль по токену из письма; после смены закрывает локальную сессию (бэкенд гасит все).
- **verify-email/page.tsx** — подтверждение почты POST-запросом (не GET — антивирусы открывают ссылки из писем сами).

## `src/components/auth/`

- **AuthProvider.tsx** — единственный источник правды о сессии. access-токен **только в ref** (не localStorage, не cookie); при загрузке сессия восстанавливается `POST /api/auth/refresh/`; параллельные обновления делят один промис (иначе две ротации сожгли бы друг другу токен). `useAuth()` → `{isLoaded, isSignedIn, userId, getToken}`.
- **AuthCard.tsx** — общая обвязка экранов входа/регистрации: маскот, стеклянная карточка, ошибка, ссылка на соседний экран.
- **useResendVerification.ts** — повторная отправка письма подтверждения (баннер и экран оформления).

## `src/components/ui/` — переиспользуемые примитивы

- **Button.tsx** — кнопка с «магнитным» эффектом; `<button>` или `<Link>`.
- **Input.tsx** — `Input` и `PasswordInput` в стиле `.inset-well`.
- **GlassCard.tsx** — стеклянная карточка с бликом за курсором.
- **GlassFilters.tsx** — SVG-фильтры преломления (`feDisplacementMap`) для «жидкого стекла»; монтируется один раз в корневом layout.
- **BrandMark.tsx** — знак-линза (геометрия марки, единый источник); **Logo.tsx** — знак + словесная марка.
- **Mascot.tsx** — маскот: стеклянная сфера с лицом, настраиваемые выражение, тон, парение.
- **Marquee.tsx** — бегущая строка (логотипы вузов).
- **Reveal.tsx** — появление при скролле (только opacity/transform).
- **CookieNotice.tsx** — неблокирующее уведомление о cookie, один раз.

## `src/components/mainapp/` — приложение

### Экран чата

- **ChatScreen.tsx** — общий экран трёх режимов: пустой экран с hero-композером либо тред + композер снизу. Логика — в `useChatSession`.
- **useChatSession.ts** — «мозг» чата: сообщения, жизненный цикл диалога, история с кэшем, отправка и повтор, подписка на живой ответ в `chat-stream`, «Стоп», обработка лимитов и плашек.
- **ChatComposer.tsx** — поле ввода: текст (≤400 000 символов), вложения (белый список совпадает с бэкендом), ряд сценариев, переключатели размышления (замок на Free) и усилия.
- **ChatEmpty.tsx** — приветствие пустого чата.
- **ChatMessage.tsx** — пузырёк: пользователь справа, ответ ИИ слева в Markdown; плашки деградации/лимита/остановки, источники веб-поиска, выгрузка в `.docx`/`.md`/список литературы, индикатор «думаю».
- **Markdown.tsx** — рендер ответа (react-markdown + GFM + KaTeX). ⚠️ Рендерит недоверенный текст (вывод модели и пересказ веб-страниц) — в `href`/`src` пропускаются только разрешённые схемы (`safeUrl`).
- **CodeBlock.tsx** — блок кода: подсветка Shiki, язык и имя файла, копирование, номера строк, сворачивание длинных листингов, цитирование выделенного в композер.

### Полосы и меню

- **AppBanners.tsx** — над режимом ровно одна полоса за раз, по приоритету: предложение суточного демо Plus (пока не брали) → срок идущего демо → напоминание подтвердить почту.
- **VerifyEmailBanner.tsx** — напоминание подтвердить почту, закрываемое, с повторной отправкой.
- **AccountMenu.tsx** — ЛК в правом верхнем углу: почта, тариф, остаток самого забитого окна квоты, апселл, переходы во вкладки «Подписка»/«Платежи», выход.

### Провайдеры состояния

- **ConversationsProvider.tsx** — список диалогов: загрузка + кэш, оптимистичные create/remove/rename/togglePin. `useConversations()`.
- **SettingsProvider.tsx** — настройки `/api/me/settings/`: кэш в localStorage, тема/шрифт на `<html>`, дебаунс-PATCH. Тип `Settings` — зеркало `UserSettingsSerializer`. `useSettings()`.
- **SubscriptionProvider.tsx** — одна загрузка `/api/me/subscription/` и `/api/me/usage/` на всё приложение: тариф, возможности, квоты, триал, проценты расхода. Сайдбар, меню аккаунта, композер и вкладка «Подписка» видят одно и то же. `useSubscription()`.

### `settings/` — диалог настроек

- **SettingsDialog.tsx** — модалка: backdrop, ESC, блок скролла, навигация, открытие на нужной вкладке (ссылки из писем обязаны вести к способу отказа от списаний).
- **config.tsx** — список вкладок (метаданные + панель).
- **controls.tsx** — UI-набор: раскладка (Section/Row/Field) и элементы ввода.
- **hooks.ts** — `useMemoryFacts`; тариф и расход — из `SubscriptionProvider`.
- **index.ts** — публичный экспорт.
- **tabs/GeneralTab.tsx** — тема, размер шрифта.
- **tabs/ModelTab.tsx** — модели по режимам (замок на тирах, недоступных тарифу, — список с бэкенда), креативность, длина, глубина.
- **tabs/MemoryTab.tsx** — «о себе» (с лимитами длины), глубина контекста, автопамять.
- **tabs/SavedFacts.tsx** — сохранённые факты памяти: список и удаление.
- **tabs/SubscriptionTab.tsx** — тариф, расход по режимам и окнам, триал, управление автопродлением и картой (п. 7.4 оферты: отказ в ЛК без уговоров), апселл.
- **tabs/PaymentsTab.tsx** — история операций из `/api/billing/payments/` (с id платежа в ЮKassa).
- **tabs/DataTab.tsx** — автоудаление чатов, опасная зона: удалить все чаты, удалить аккаунт.

### `sidebar/` — боковая панель

- **AppSidebar.tsx** — оболочка: контейнер, фильтр и группировка чатов.
- **parts.tsx** — шапка, переключатель режимов, новый чат, поиск, подвал (тариф и расход).
- **ChatList.tsx** — группы по дате, строка чата с контекстным меню.
- **useChatRowMenu.ts** — поведение меню строки (портал, закрытие по клику/скроллу/ресайзу).
- **index.ts** — публичный экспорт.

## Где что искать (быстрый ориентир)

- **Логика чата, отправка, «Стоп», повтор** → `mainapp/useChatSession.ts` (+ `lib/chat-stream.ts`).
- **Запросы к бэку / стриминг** → `hooks/useApi.ts`; **без сессии** → `lib/auth-api.ts`.
- **Сессия, вход, охрана маршрутов** → `auth/AuthProvider.tsx` + `app/(modes)/layout.tsx`.
- **Тариф, квоты, триал на клиенте** → `mainapp/SubscriptionProvider.tsx`.
- **Список чатов, переименование/удаление/закрепление** → `mainapp/ConversationsProvider.tsx` + `sidebar/`.
- **Настройки пользователя** → `mainapp/SettingsProvider.tsx` + `settings/`.
- **Любой текст интерфейса** → `content/`; **коды, которые читает бэк** → `types/`.
- **Подсветка кода** → `mainapp/CodeBlock.tsx` + `lib/highlighter.ts`; **Markdown и формулы** → `mainapp/Markdown.tsx`.
- **Клиентские лимиты длины** → `lib/limits.ts` (зеркало бэкенда).
- **Цвета, стекло, тёмная тема, стили Markdown** → `app/globals.css`.
- **Заголовки безопасности, CSP** → `middleware.ts`.
