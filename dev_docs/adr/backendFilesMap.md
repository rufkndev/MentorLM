# Карта файлов бэкенда

Django 5.2 + DRF. Проектный пакет — `mentorlm_api/`, приложения — в `apps/`.
Авторизация своя (email + пароль, JWT access + refresh-cookie), база — свой
Postgres в docker (152-ФЗ). Подробное описание — `backenddescription.md`, все
числа экономики — `economicsAndLimits.md`.

## `backend/` — вокруг проекта

- **requirements.txt** — зависимости: Django, DRF, PyJWT, openai, anthropic, httpx[socks] (прокси), tiktoken, psycopg, redis, pypdf, python-docx, markdown-it-py (экспорт), gunicorn, whitenoise. Плюс заделы на будущее, пока не используются: langchain/langgraph, pgvector, SDK Яндекса.
- **gunicorn.conf.py** — воркеры прода: `gthread`, 2 × 16 потоков, `timeout 1200` — SSE-ответ «Исследовать» длится до 900 с, sync-воркер его бы убил.
- **Dockerfile.dev / Dockerfile.prod** — образы бэкенда.
- **mentorlm/manage.py** — management-команды; по умолчанию `settings.dev`.

## `mentorlm_api/` — конфигурация проекта

- **settings/base.py** — всё, что не зависит от окружения: приложения, Postgres из `POSTGRES_*`, параметры соединения с Redis, DRF (свой auth-класс, `IsAuthenticated` по умолчанию, троттлинг по scope), сроки токенов и cookie, версии политики ПДн и оферты, почта Postbox, ключи ЮKassa, прокси и ключи LLM. Моделей здесь нет.
- **settings/dev.py** — DEBUG, CORS с credentials, кэш: Redis по `REDIS_URL` или явный `ALLOW_LOCMEM_CACHE=1`, иначе старт падает; письма в консоль, пока нет `POSTBOX_SECRET`.
- **settings/prod.py** — падает на старте без обязательных переменных (секрет, хосты, CSRF, Redis, Postbox, ЮKassa, адрес сайта); whitenoise, HTTPS, HSTS, secure-cookie, логи.
- **settings/__init__.py** — пояснение, как выбирается модуль настроек.
- **urls.py** — `/admin/` и API шести приложений под общим префиксом `/api/`.
- **wsgi.py / asgi.py** — точки входа серверов.

## `apps/core/` — служебное

- **views.py** — `GET /api/health/`, публичный (без токена), БД не проверяет.
- **urls.py** — маршрут health-check.
- **admin_site.py** — свой `AdminSite`: главная админки — дашборд. Блок «Требует внимания» появляется только когда нужно действие руками (чеки НПД, автопродление без привязки, `past_due`, зависшие возвраты и платежи, неотправленные письма) и ведёт в отфильтрованный список; ниже — плитки метрик.
- **admin_config.py** — подключает этот `AdminSite` вместо `django.contrib.admin` в `INSTALLED_APPS`.
- **templates/admin/mentorlm_index.html** — шаблон дашборда.
- **net.py** — `client_ip()`: IP клиента за nginx (правый адрес `X-Forwarded-For`). Одно определение для лимитов входа, согласий и вебхука.

## `apps/users/` — учётка, сессии, личный кабинет

- **models.py** — `UserProfile` (email, хэш пароля, `email_verified`, согласие на ПДн — момент/версия/IP; поля `plan` нет), `UserSettings` (1:1, настройки по вкладкам ЛК; варианты, дефолты и лимиты длины — из `ai/preferences.py`), `RefreshToken` (sha256 + устройство), `EmailToken` (ссылки из писем: подтверждение почты и сброс пароля).
- **tokens.py** — единственный источник правды о сессиях: выпуск и проверка access-JWT, выпуск/ротация/отзыв refresh, детекция повтора украденного токена, одноразовые токены из писем. В докстроке — почему схема такая.
- **authentication.py** — `SessionJWTAuthentication`: проверяет access по подписи и кладёт `UserProfile` в `request.user`. Дефолтный auth-класс всего API.
- **auth_views.py** — публичные эндпоинты сессии и писем: регистрация (с согласием на ПДн), вход, refresh, выход, смена пароля, подтверждение почты, сброс пароля. Лимиты попыток входа и отправки писем в Redis, письмо о смене пароля.
- **permissions.py** — `EmailVerified`: вешается на все платёжные эндпоинты и триал, отвечает `403 email_not_verified`.
- **views.py** — `/api/me/` (GET; DELETE — удалить аккаунт каскадом), `/api/me/settings/` (+ `/defaults/`), `/api/me/usage/` (проценты по окнам квоты каждого режима), `/api/me/subscription/` (тариф, автопродление, карта, возможности тарифа, квоты, состояние триала).
- **serializers.py** — профиль (тариф считается на лету) и настройки; поля «о себе» ограничены по длине и чистятся `ai.sanitize` до записи. `settings_defaults()` берёт дефолты из модели.
- **urls.py** — маршруты `/api/auth/*` и `/api/me/*`.
- **admin.py** — профили с настройками инлайном, действующим тарифом и живыми процентами квот (тот же `mode_usage_report`, что в ЛК); refresh-токены и токены писем.

## `apps/ai/` — слой работы с LLM

Своих моделей и URL нет: сервис, который вызывает вьюха диалога. Клиент присылает только `mode` + `scenario_id` (+ переключатели `thinking`/`effort`), всё остальное собирается на бэке.

- **service.py** — фасад и единственная точка входа: `run_conversation_stream()` — сценарий, согласование настроек, модель (или деградация), память по тарифу, промпт, история, инструменты, параметры, провайдер. Возвращает поток дельт, реальную модель, усилие и словарь `usage`.
- **registry.py** — реестр режимов: базовые промпты (`CHAT_PROMPT`, `CODE_PROMPT`, `RESEARCH_PROMPT`), общие `RENDER_RULES` (LaTeX, знак доллара) и `SAFETY_RULES` (данные ≠ инструкции), сценарий по умолчанию. Здесь меняют **тон**; провайдер и модели — из `billing/limits.py`.
- **scenarios.py** — реестр 15 сценариев: системный промпт + полный пресет генерации (температура и коридор, длина, предыстория, инструменты, формат, аудитория, стиль, усилие, проверки, а для «Кода» — принципы, комментарии, вид вывода, язык). `get_scenario`, `is_known_scenario`.
- **preferences.py** — настройки «Модель ИИ» и «Память»: канонические `*_CHOICES`, `DEFAULTS`, `PERSONA_LIMITS`, `RETENTION_CHOICES`; правила мягкого сдвига (`resolve_preferences`), персона, `resolve_model()` с зажатием тира тарифом.
- **prompts.py** — сборка системного промпта: база режима + сценарий + директивы из структурных полей + `UNTRUSTED_NOTICE` + персона + память. Словари расшифровки значений полей в русские директивы.
- **sanitize.py** — обработка любого чужого текста перед промптом: `clean_prompt_text()` (маркеры ролей, невидимые символы, наши теги, лимит длины и строк) и `wrap_untrusted()` (`<user_data>`, `<memory>`, `<file>`, `<dialogue>`).
- **context.py** — история диалога для модели: последние ≤ N сообщений вида `text` + текст их вложений, обрезка ступенями (`_history_window`, чтобы работал кэш промптов), текущий вопрос всегда; `_normalize` — старт с `user` и чередование ролей (требование Anthropic). `count_tokens()` для предохранителей.

### `apps/ai/providers/` — реализации провайдеров

- **base.py** — контракт: `GenParams` (модель, температура, инструменты, усилие, размышление, потолок вывода) и протокол `LLMProvider.stream()`.
- **__init__.py** — реестр провайдеров и `get_provider()` по ключу режима.
- **_clients.py** — единая сетевая политика: прокси `LLM_PROXY_URL`, таймауты (соединение / пауза между кусками / отправка), ретраи только на запуске, пул соединений на процесс.
- **_openai.py** — `create_with_optional()`: необязательные опции снимаются по ответу 400 и запоминаются по модели; `effort_for()` — подъём усилия при размышлении; `cache_options()` — `prompt_cache_key` и `prompt_cache_retention` для кэша промптов.
- **openai_chat.py** — режим «Общий», Chat Completions.
- **anthropic.py** — режим «Код», Messages API: усилие через `output_config.effort`, размышление `adaptive`, снятие отвергнутых опций.
- **openai_research.py** — режим «Исследовать», Responses API + `web_search`: потолок поисков `max_tool_calls`, учёт платных вызовов, чистка служебных псевдо-тегов, сбор источников из `url_citation`.

## `apps/conversations/` — диалоги и главный эндпоинт чата

- **models.py** — `Conversation` (режим, сценарий диалога, заголовок, закрепление), `Message` (роль; вид `text` или `notice` — уведомление о лимите, модели не передаётся; `meta` для плашек и источников), `Attachment` (извлечённый текст, сам файл не храним).
- **views.py** — список (с ленивой чисткой по сроку хранения) / создание / удаление всех, деталь (+ флаг `generating`), `POST /api/conversations/{id}/messages/`: разбор полей и `retry` → вложения по тарифу → лок генерации → preflight → сохранение вопроса → SSE через поток-читатель с пульсом, «Стопом» и таймаутом режима → сохранение ответа, списание расхода, память. Плюс `POST /conversations/stop/`.
- **attachments.py** — политика приёма файлов (тариф, число, размер, белый список форматов), извлечение текста из PDF/DOCX/текстовых и файлов кода, блок `<file>` для промпта с нумерацией строк кода.
- **export_views.py** — `GET /conversations/{id}/messages/{mid}/export/{docx|md|sources}/`: ответ файлом. Отдельно от `views.py`, чтобы не тянуть python-docx в горячий путь.
- **export/__init__.py** — `build_docx()` (ответ) и `build_sources_docx()` (список литературы по ГОСТ Р 7.0.5-2008).
- **export/gost.py** — все числа ГОСТ 7.32-2017 константами (шрифт, кегль, поля, отступы), стили документа, номер страницы.
- **export/md_to_docx.py** — обход Markdown в абзацы, списки, таблицы и код `.docx`.
- **serializers.py** — краткий вид для сайдбара (заголовок ≤120 символов, чистится) и полный с историей; извлечённый текст вложений наружу не отдаётся.
- **urls.py** — маршруты диалогов (`stop/` выше `<int:pk>/`).
- **admin.py** — диалоги, сообщения, вложения (вложения — только чтение).

## `apps/billing/` — тарифы, лимиты, подписки, платежи

- **limits.py** — единственный файл настройки экономики: **каталог моделей** (`MODELS` — цены ввода, вывода и кэша промптов, `MODES` — провайдер, модель на каждый тир и модель деградации, `MEMORY_MODEL`), `usage_cost`, `clamp_tier`, глобальные потолки (включая шаг обрезки предыстории `CONTEXT_TRIM_STEP`), скользящие окна, grace деградации, доли режимов, параметры триала, `PLAN_LIMITS`, **цены подписки** (`PLAN_PRICE_RUB`), правила продления, курс для возвратов, налоговый режим и сроки чеков НПД. Расход в микро-долларах.
- **checks.py** — системные проверки каталога на `check`/`migrate` (E001–E011, W001–W003): у модели есть цена и цены кэша в верном порядке, провайдер существует, режимы во всех словарях, доли = 1, тиры совпадают с UI, у тарифов есть лимиты, цена и флаги, триал бесплатный. В проде `migrate` идёт до gunicorn — кривой каталог не даёт контейнеру подняться.
- **guard.py** — `preflight()`: размышление на тарифе → rate limit → длина ввода → квоты окон режима; возвращает `Decision(degrade, thinking, plan)` или бросает `LimitExceeded`. Здесь же лок генерации, флаг «Стоп», ожидание конца ответа и `mode_usage_report` — единственное место, где окна превращаются в проценты.
- **plans.py** — `alive_subscriptions()` (одно определение «действует»), `active_subscription()`, `effective_plan()`; `PAST_DUE_GRACE`.
- **trial.py** — суточный пробный Plus: `start_trial()` (идемпотентно, один на аккаунт), `trial_state()` для ЛК. Без карты и автопродления.
- **models.py** — `Plan` (единственное объявление тарифов: free/trial/plus/pro), `Subscription` (состояние + автопродление и привязка), `Payment`/`Refund` (реестр денег), `BillingEvent` (журнал согласий), `log_event()`. Словари для показа: способы оплаты, причины отказа банка, `AUTO_RENEW_METHODS`.
- **yookassa.py** — HTTP-контракт с провайдером: basic-авторизация, `Idempotence-Key`, ретраи, обработка `202`. Прокси НЕ использует.
- **payments.py** — **вся логика денег**: оформление, автосписание и все условия раздела 7 оферты (`renewal_blocked_reason`), применение статусов, отказ от автопродления и его возврат, удаление карты, расчёт и проведение возвратов, чеки НПД. Единственное место, где собирается запрос к ЮKassa.
- **views.py** — `/api/billing/plans/` (публично), `trial/`, `checkout/`, `payments/` (+ деталь с перезапросом статуса), `subscription/cancel/`, `subscription/resume/`, `payment-method/` (DELETE).
- **serializers.py** — платежи для ЛК и `/billing/return` (с человеческой причиной отказа).
- **urls.py** — маршруты `/api/billing/*`.
- **webhooks.py** — приём уведомлений ЮKassa: аллоу-лист сетей (IP из `X-Forwarded-For` **справа**), перечитывание состояния через API, всегда 200.
- **management/commands/billing_tick.py** — планировщик раз в 10 минут (сервис `scheduler`): уведомления за 24 ч, письма об окончании, списания, досинхронизация зависших платежей, авто-возвраты по п. 7.6, напоминания о чеках НПД. `--dry-run`.
- **management/commands/npd_receipts_reset.py** — разово закрыть текущий список «ждут чека НПД» без писем покупателям (тестовые оплаты, чеки, выписанные вне системы). `--apply`, `--url`.
- **templates/admin/billing/** — страницы оформления возврата (с расчётом по п. 11.2) и выдачи чека НПД.
- **admin.py** — подписки с признаком «действует сейчас» и действием отключения автопродления, реестр платежей только на чтение, возвраты, журнал событий. Ручная выдача тарифа — здесь.

## `apps/usage/` — учёт расхода ИИ

- **models.py** — `UsageEvent` (журнал запросов: режим, сценарий, модель, тариф, усилие, токены, поиски, µ$, деградация, размышление — источник правды для квот и возвратов) и `Usage` (дневной роллап для админки, в лимитах не участвует).
- **services.py** — `record_usage()`: событие в журнал + атомарный инкремент дневной строки. Вызывается после каждого ответа, включая прерванные.
- **admin.py** — журнал только на чтение, дневные срезы (можно только удалять).

## `apps/memory/` — глобальная память о пользователе

- **services.py** — `build_memory_block()` подмешивает факты в промпт, `extract_facts_in_background()` после ответа извлекает до трёх новых фактов дешёвой моделью в фоновом потоке и списывает расход в квоту режима. Только платные тарифы. Ошибки памяти никогда не ломают ответ.
- **models.py** — `UserMemoryFact`: факт уровня аккаунта, а не диалога.
- **views.py / serializers.py / urls.py** — `/api/memory/facts/`: показать и удалить сохранённые факты.
- **admin.py** — просмотр накопленных фактов.

## `apps/mailer/` — исходящая почта

- **letters.py** — каталог писем: тема + шаблоны `.html`/`.txt` на каждое.
- **sender.py** — `send()`: отправка в фоновом потоке, ошибки глушатся, каждая попытка пишется в журнал.
- **models.py** — `SentLetter`: журнал попыток с ответом транспорта (доказательство уведомления о списании). Адрес — снимком, не ссылкой.
- **templates/emails/** — шаблоны писем: подтверждение почты, сброс и смена пароля, оплата, уведомление о списании, неудачное списание, окончание и отмена подписки, возврат, чек НПД, напоминание оператору о чеках.
- **admin.py** — журнал писем только на чтение.

## Где что искать (быстрый ориентир)

- **Отправка сообщения, SSE, «Стоп», повтор** → `conversations/views.py`.
- **Выгрузка ответа в Word / список литературы** → `conversations/export_views.py` + `conversations/export/`.
- **Поменять модель режима или тира** → `billing/limits.py` (`MODES`), там же её цена; **тон режима** → `ai/registry.py`; **поведение сценария** → `ai/scenarios.py`.
- **Как настройки пользователя влияют на генерацию** → `ai/preferences.py`.
- **Сборка системного промпта** → `ai/prompts.py`; **история для модели** → `ai/context.py`; **чужой текст в промпте** → `ai/sanitize.py`.
- **Цены, квоты, тарифы, модели, потолки — любые числа экономики** → `billing/limits.py` (сводка — `economicsAndLimits.md`).
- **Почему запрос отклонён по лимиту** → `billing/guard.py`.
- **Какой тариф у пользователя** → `billing/plans.py` (`effective_plan`); **триал** → `billing/trial.py`.
- **Оплата, автосписание, возврат** → `billing/payments.py`; **что делает планировщик** → `billing/management/commands/billing_tick.py`.
- **Куда пишется расход** → `usage/services.py` → `usage.UsageEvent`.
- **Вход, токены, письма-ссылки** → `users/tokens.py`, `users/auth_views.py`.
- **Какие письма уходят и ушли ли** → `mailer/letters.py`, `mailer.SentLetter` в админке.
- **Ключи, кэш, CORS, троттлинг** → `mentorlm_api/settings/` и `infra/env/.env`.
