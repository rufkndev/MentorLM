# Экономика и лимиты

Всё, что ограничивает пользователя и наш расход: деньги, квоты, модели, потолки
ввода и вывода, частоты запросов, файлы, память, сеть.

Источник правды по экономике — **`backend/mentorlm/apps/billing/limits.py`**.
Остальные числа живут рядом с кодом, который их применяет (файл указан в каждой
таблице). Числа сняты с кода **02.10.2026** (коммит `9d91e3b economics change` +
кэширование промптов и новые цены `claude-sonnet-5` / `gpt-5.6-sol`).
Поменяли число в коде — поправьте его здесь.

## 1. Единица учёта

Расход считается в **микро-долларах (µ$)**, целыми числами: $1 = 1 000 000 µ$.
Float не используется — при суммировании журнала он копил бы ошибку.

```
стоимость (µ$) = (tokens_in − cache_read − cache_write) × цена_входа
               + cache_read × цена_чтения_кэша + cache_write × цена_записи_в_кэш
               + tokens_out × цена_выхода
               + web_search_calls × WEB_SEARCH_CALL_COST
```

Цена в $/1M токенов численно равна µ$ за токен, поэтому формула сразу даёт µ$
(`usage_cost()` в `limits.py`). Поле БД называется `billable_tokens` — имя
историческое, внутри µ$.

- **Квота списывается по реальному расходу, с учётом кэша промптов.**
  `tokens_in` — весь ввод запроса; `cache_read_tokens` / `cache_write_tokens` в
  `UsageEvent` — его часть, взятая из кэша провайдера или записанная в него.
  Кэш дешевле обычного ввода — и пользователю списывается меньше. Как кэш
  включён и что его ломает — п. 7.7.

- Токены размышления (reasoning / thinking) провайдеры уже включают в
  `tokens_out` — отдельной статьи расхода нет, `thinking_tokens` в журнале только
  для аналитики.
- Модель, которой нет в каталоге (например, убранная, но оставшаяся в старом
  журнале), считается по `DEFAULT_PRICE = (5.00, 30.00, 5.00, 6.25)` — не ниже
  самой дорогой модели каталога по каждому полю и без скидки за кэш (иначе её
  «удаление» удешевило бы расход). Проверка — `billing.W001`.
- Квоты задаются в долларах и хранятся в тех же µ$ — сравнение в одной единице.
- Расход списывается **всегда**, даже если ответ прерван «Стопом», упал или
  пришёл пустым: провайдер деньги уже взял. На обрыве выход оценивается
  tiktoken'ом по написанному тексту. ⚠️ Ввод на обрыве сейчас записывается как
  0: usage провайдеры отдают только в конце стрима (у Anthropic вход известен
  уже из `message_start`, но поток чтения закрывается асинхронно). Известная
  недоучётка, отдельная задача.

(`WEB_SEARCH_CALL_COST = 10_000` µ$), не больше **8 вызовов на один ответ**

`max_tool_calls`; если API его не принял — `openai_research.py` обрывает поиск сам.

## 3. Чем отвечает каждый режим

`limits.MODES`. Тир — настройка пользователя «Модель ИИ» (поля
`chat_model` / `code_model` / `research_model` в `UserSettings`).

| Режим                    | Провайдер (API)                       | Быстрая            | Стандартная (дефолт) | Максимальная     | Деградация         | Веб-поиск |
| ------------------------ | ------------------------------------- | ------------------ | -------------------- | ---------------- | ------------------ | --------- |
| Общий `chat`             | `openai_chat` (Chat Completions)      | `gpt-5.6-luna`     | `gpt-5.6-terra`      | `gpt-5.6-sol`    | `gpt-5-nano`       | нет       |
| Код `code`               | `anthropic` (Messages API)            | `claude-haiku-4-5` | `claude-sonnet-5`    | `claude-opus-5`  | `claude-haiku-4-5` | нет       |
| Исследовать `research`   | `openai_research` (Responses API)     | `gpt-5.6-luna`     | `gpt-5.6-terra`      | `gpt-5.6-sol`    | `gpt-5-nano`       | да        |

Фоновое извлечение памяти — `MEMORY_MODEL = gpt-5-nano`.

**Зажатие тира (`clamp_tier`).** Если выбранный тир тарифу недоступен, отказа нет —
тир молча спускается по цене (`quality → default → fast`) до первого
разрешённого. Тир — это сохранённая настройка: человек мог выбрать
«Максимальную» на Plus и уйти на Free, и отказ на каждом сообщении выглядел бы
поломкой. Апселл живёт в настройках (замок на недоступном тире).

## 4. Сколько стоит ответ (ориентир)

Профиль ответа взят из dev-журнала `UsageEvent` (выборка маленькая — 19 / 4 / 12
ответов, это ориентир, а не статистика):

- «Общий»: ~1 600 токенов вход / ~430 выход;
- «Код»: ~1 900 вход / ~4 800 выход (код длинный, выход дорогой);
- «Исследовать»: ~11 600 вход / ~1 000 выход + 1 поиск (найденные страницы
  раздувают вход).

| Режим       | Быстрая  | Стандартная | Максимальная | Деградация |
| ----------- | -------- | ----------- | ------------ | ---------- |
| Общий       | $0.0008  | $0.0084     | $0.0150      | $0.0003    |
| Код         | $0.0259  | $0.0518     | $0.1295      | $0.0259    |
| Исследовать | $0.0135  | $0.0452     | $0.0764      | $0.0010 (без поиска) |

Это цена ответа **без кэша** — то есть первого хода или короткого диалога. С
третьего-четвёртого хода и с вложениями история и файлы читаются из кэша по
0.1× цены ввода, и ход дешевеет: например, «Код» на Sonnet, 10 ходов по ~300
токенов вопроса и ~800 ответа — около $0.30 за диалог без кэша и $0.18 с ним;
с файлом на 20k токенов — около $0.78 и $0.26 (оценка, проверять по
`cache_read_tokens` в журнале).

Извлечение памяти после ответа: ~1 000 вход / ~400 выход на `gpt-5-nano` ≈
**$0.0002** — копейки, но списывается в квоту режима, породившего ответ.

Потолок одного ответа (100k вход + 10k выход, без кэша): от $0.009
(`gpt-5-nano`) до $0.60 (`gpt-5.6-sol`) / $0.75 (`claude-opus-5`).

## 5. Тарифы

### 5.1 Цены и бюджеты

| Тариф       | Код     | Цена / мес | Нетто*   | Бюджет на модели / мес | Как задан                                  |
| ----------- | ------- | ---------- | -------- | ---------------------- | ------------------------------------------ |
| Бесплатный  | `free`  | 0 ₽        | —        | **$0.50** (≈ 53 ₽)     | `_plan_quotas(0.5, burst_share=0.4)`       |
| Пробный Plus| `trial` | 0 ₽ (не продаётся) | — | **$0.80 на 24 часа**  | `_plan_quotas(0.8, weeks=1, burst_share=1.0)` |
| Plus        | `plus`  | **1 499 ₽**| $13.3    | **$12**                | `_plan_quotas(12.0)`                       |
| Pro         | `pro`   | **2 499 ₽**| $22.1    | **$23**                | `_plan_quotas(23.0)`                       |

\* Нетто = цена − эквайринг (~3%) − НПД (4%), при курсе 105 ₽/$.

- **Бюджет — это потолок убытка**: выберет человек квоту полностью — мы заплатим
  провайдеру ровно эту сумму. Поэтому он выводится из нетто, а не назначается на
  глаз. Пересчитывать при каждой смене цены подписки, курса или прайса моделей.
- **Pro — единственный тариф, уходящий в минус при полной выборке** (~−90 ₽):
  осознанная ставка, что 100% квоты не выбирает никто. Безубыточный потолок Pro —
  $20.4; если фактическая выборка окажется высокой — снижать здесь.
- **Free** $0.5/мес на каждого зарегистрированного: при марже Plus ~900 ₽ один
  платящий кормит ~16 бесплатных.
- Цена подписки задана **только** в `PLAN_PRICE_RUB`. Фронт берёт её с
  `GET /api/billing/plans/` (`usePlanPrices`); числа в `content/billing.ts` —
  запасные на случай недоступного API.
- Тестовая цена ставится без правки кода: `PLAN_PRICE_PLUS` / `PLAN_PRICE_PRO`
  в `infra/env/.env` (минимум ЮKassa — 1 ₽). ⚠️ В текущем локальном `.env` стоят
  **10 и 20 ₽** — перед продом проверить, что на сервере их нет.
- Цена триала обязана быть 0 (системная проверка `billing.E010`): на этом
  держится то, что планировщик не шлёт о нём писем о продлении.

`limits.PLAN_LIMITS`. Отдаётся клиенту целиком через `GET /api/me/subscription/`
— интерфейс узнаёт доступность возможностей отсюда, а не из названия тарифа.

| Возможность                         | Free           | Пробный Plus      | Plus        | Pro         |
| ----------------------------------- | -------------- | ----------------- | ----------- | ----------- |

| Веб-поиск в «Исследовать»           | нет            | да                | да          | да          |
| Глобальная память (`allow_memory`)  | нет            | да                | да          | да          |

| Предыстория диалога (`context_messages`) | 4 сообщения | 10           | 10          | 10          |

- Free урезан **по объёму, а не по качеству**: предыстория есть у всех, иначе

- Триал не даёт «Максимальную»: ~$0.14 за ответ, суточный бюджет кончился бы за
  пять вопросов.

### 5.3 Квоты по режимам и окнам

Две **скользящих** окна (`QUOTA_WINDOWS`), как в Claude Code: **5 часов**
(`burst`) и **7 дней** (`week`). Квоты **отдельные для каждого режима** —
исчерпанный «Код» не мешает «Общему». Считаются как `SUM(billable_tokens)` по
`UsageEvent` за окно (`guard._window_usage`).

Как месячный бюджет превращается в квоты (`_plan_quotas`):

1. Бюджет делится по режимам в постоянных долях `_MODE_SHARES`:
   **Общий 5/12, Код 4/12, Исследовать 3/12** (одни на все тарифы).
2. Неделя режима = доля / `WEEKS_PER_MONTH` (**4.348**, а не 4: скользящее окно
   не знает календаря, за месяц укладывается 4.35 окна). Неделя — главный потолок.
3. 5-часовое окно = `BURST_SHARE_OF_WEEK` × неделя: **25%** по умолчанию, **40%**
   на Free (бесплатный приходит одной сессией), **100%** на триале (окно не
   ограничивает — суточное демо проходят одной-двумя сессиями).

## 6. Что происходит при исчерпании квоты

Порядок проверок — `billing.guard.preflight`, до старта SSE и до сохранения
вопроса:

1. **Размышление на тарифе без него** → `402 feature_locked`.
2. **Rate limit** — 5 запросов в минуту → `429 rate_limited`.
3. **Длина ввода** > 100 000 токенов → `413 input_too_long`.
4. **Квоты окон** режима:
   - окно не исчерпано → ответ как обычно;
   - окно исчерпано, но **grace-ответы остались** → **деградация**: ответ на
     дешёвой модели режима и **без веб-поиска**, на фронт уходит плашка
     `{degraded: true}`, в журнале `degraded=True`;
   - grace кончился → `429 mode_quota_exceeded` с моментом восстановления окна.

Число grace-ответов на окно (`DEGRADE_REQUESTS`): **Общий 5, Код 2,
Исследовать 5**. Считаются как число `degraded=True` событий в исчерпанном окне,
поэтому «отпускают» вместе с окном. У «Кода» меньше потому, что его дешёвая
модель (Haiku) на порядок дороже дешёвых OpenAI — грейс приходится ограничивать
числом, а не ценой.

`feature_locked` и `mode_quota_exceeded` сохраняются в диалог сообщением-
уведомлением (`Message.kind = notice`, в `meta` — код и `can_upgrade`): плашка
с апселлом остаётся после ухода на `/billing` и возврата. Модели такие сообщения
не передаются.

**Размышление снимается молча** (ответ приходит обычным), если: идёт деградация,
или в любом окне режима осталось меньше **10%** (`THINKING_MIN_REMAINING`) —
размышление легко утраивает объём ответа.

**Триал не попадает в окна других тарифов** (`guard._ledger`): его суточный
бюджет в 7 раз больше всей недельной нормы Free, и иначе человек выходил бы из
демо заблокированным почти на неделю. Обратное правило («считать только текущий
тариф») не вводится — смена тарифа обнуляла бы счётчик.

**Тариф ответа фиксируется в начале.** Ответ «Исследовать» пишется до 900 с, и
триал может истечь посреди стрима — расход записывается за тот тариф, чью квоту
проверил preflight (`Decision.plan`).

## 7. Глобальные потолки (едины для всех тарифов)

### 7.1 Генерация

| Ограничение                         | Значение                                     | Где                        | Что происходит |
| ----------------------------------- | -------------------------------------------- | -------------------------- | -------------- |
| Длина сообщения в символах          | **400 000**                                  | `limits.MAX_MESSAGE_CHARS` | `413 input_too_long` до токенизации (дешёвый предохранитель) |
| Длина ввода в токенах (вопрос + текст вложений) | **100 000**                      | `limits.MAX_INPUT_TOKENS`  | `413 input_too_long`, модель не вызывается |
| Длина ответа                        | **10 000** токенов                           | `limits.MAX_OUTPUT_TOKENS` | обрез провайдером. Это предохранитель от зацикливания, длину задаёт промпт. ⚠️ У OpenAI в потолок входят токены рассуждения |
| Предыстория диалога                 | `min(сценарий × «Глубина контекста», тариф, 30)` сообщений | `ai.service`, `MAX_CONTEXT_MESSAGES = 30` | последние ≤ N, обрезка ступенями по `CONTEXT_TRIM_STEP = 6` (п. 7.7); текущий вопрос уходит всегда |
| Частота                             | **5** запросов в минуту на пользователя      | `limits.RATE_PER_MIN`      | `429 rate_limited` (окно — календарная минута в Redis) |
| Параллельность                      | **1** ответ за раз на пользователя           | `guard` (лок `genlock:{id}`) | ждём до 5 с (`LOCK_WAIT_SECONDS`), затем `429 generation_in_progress` |
| Время генерации                     | Общий **180 с**, Код **300 с**, Исследовать **900 с** | `limits.REQUEST_TIMEOUT_SECONDS` | ответ обрывается, написанное сохраняется, в `done` — ошибка «Превышено время ответа» |
| TTL лока генерации                  | 900 + 60 = **960 с**                         | `guard._GEN_LOCK_TTL`      | аварийный — на случай смерти воркера |
| Ожидание «Стопа»                    | до **10 с**                                  | `guard.STOP_WAIT_SECONDS`  | `{stopped: false}` — фронт рвёт соединение сам |
| Веб-поиск                           | ≤ **8** вызовов на ответ, $0.01 за вызов      | `limits.WEB_SEARCH_*`      | — |

Длина предыстории на практике: база сценария (18–36 сообщений) × множитель
«Глубины контекста» (компактно ×0.5, обычно ×1, глубоко ×1.6, максимум ×4, не
меньше 2) → зажимается тарифом (Free 4, остальные 10) → потолком 30. То есть
сейчас реальный потолок задаёт **тариф**, а настройка влияет только при
«Компактно» на коротких сценариях.

Окно обрезается не по одному сообщению, а ступенями по 6 (3 хода,
`ai.context._history_window`): при потолке 10 модель видит 6 / 8 / 10 прошлых
сообщений по кругу, при потолке 4 — 2 / 4. Окно никогда не длиннее потолка
тарифа. Зачем — п. 7.7.

### 7.2 Вложения

`apps/conversations/attachments.py` + `PLAN_LIMITS.max_attachments`.

- Файлы кода нумеруются по строкам («12| …»), чтобы модель могла сослаться на строку.
- ⚠️ Фронт (`src/lib/limits.ts`) показывает **5 файлов** для всех тарифов — на Pro
  он строже сервера (там 10).

### 7.7 Кэш промптов

Провайдер хранит **начало запроса**, совпадающее байт в байт с прошлым, и
берёт за него ~0.1× цены ввода. Порядок запроса: system → история (с текстом
вложений) → новый вопрос. Значит, кэш окупается в длинных диалогах и с
большими вложениями; сам system-промпт (400–800 токенов) ниже порога кэша и
выигрыша не даёт.

| Параметр | Anthropic («Код») | OpenAI («Общий», «Исследовать», память) |
| --- | --- | --- |
| Как включён | `cache_control={"type": "ephemeral"}` — автоматическая метка на последнем блоке, двигается вместе с диалогом (`providers/anthropic.py`) | всегда включён сам; плюс `prompt_cache_key = "mlm-conv-{id}"` и `prompt_cache_retention = "24h"` (`_openai.cache_options`) |
| Минимум префикса | 1 024 токена (Sonnet 5), 512 (Opus 5), **4 096 (Haiku 4.5)** — тир «Быстрая» кэшируется редко | 1 024 токена |
| Время жизни | **5 минут** с начала запроса, каждое чтение продлевает | до 24 часов |
| Цена записи | 1.25× ввода | без наценки |
| Цена чтения | 0.1× ввода | 0.1× ввода |
| Где в usage | `cache_read_input_tokens`, `cache_creation_input_tokens` (в `input_tokens` **не** входят — складываем сами) | `prompt_tokens_details.cached_tokens` / `input_tokens_details.cached_tokens` (входят в ввод) |

Опции кэша необязательные: модель, которая их не примет, ответит без кэша
(снятие по 400, как с остальными опциями).

**Что мы делаем, чтобы начало запроса не менялось:**
- Предыстория обрезается ступенями по 6 сообщений, а не по одному
  (`CONTEXT_TRIM_STEP`, п. 7.1): иначе в длинном диалоге окно сдвигалось бы
  каждый ход, и кэш промахивался бы на каждом ходе.
- Блок глобальной памяти собирается только из фактов, известных к началу
  диалога (п. 7.4): фоновое извлечение добавляет факты по ходу разговора, и без
  этого каждый новый факт менял бы system и сбрасывал кэш всей истории.

**Что сбрасывает кэш (один промах, дальше снова попадания):** смена модели
(тир, деградация), переключатель «размышление» и смена усилия (директива в
system, у Claude ещё и `output_config.effort`), правка персоны, «Глубины
контекста» или фактов памяти, сдвиг окна предыстории (раз в 3 хода), пауза
больше 5 минут у Claude.

**Batch API** (−50%, ответ до 24 часов) не используется: все ответы
пользователю стримятся, а единственная фоновая задача — извлечение памяти на
`gpt-5-nano` — стоит доли цента.

## 10. Наблюдения (на что смотреть)

- **Free «Код» почти недоступен**: квота $0.038/нед, ответ на Haiku ≈ $0.026 →
  ~1.5 ответа в неделю плюс 2 деградационных (на той же Haiku). Если «Код» на Free
  должен работать — поднимать долю «Кода» в Free или дать ему другую модель.
- **Plus «Код» и «Исследовать» на «Стандартной» — около 4 ответов за 5 часов и
  15–18 в неделю (без кэша).** Это узкое место тарифа; проверить по реальному
  журналу, когда выборка станет большой.
- **Доля кэша** — главная новая метрика: `SUM(cache_read_tokens) /
  SUM(tokens_in)` по `UsageEvent` в разрезе режима и модели (колонка видна в
  админке журнала). Если у «Кода» она низкая при длинных диалогах — студенты
  отвечают реже раза в 5 минут, и стоит попробовать кэш на 1 час (запись 2×
  ввода вместо 1.25×; добавить цену записи на 1 час в `ModelPrice` и учитывать
  `usage.cache_creation.ephemeral_1h_input_tokens`).
- **Pro при полной выборке в минусе** (~−90 ₽). Безубыточный потолок — $20.4.
- **Локальный `.env` содержит тестовые цены 10/20 ₽.**
- **`MAX_OUTPUT_TOKENS = 10 000` включает рассуждение у OpenAI**: на усилии «high»
  длинный отчёт может упереться в потолок. Если проявится — делать потолок по
  режимам, как `REQUEST_TIMEOUT_SECONDS`.
- **«Глубина контекста» почти ни на что не влияет**: сценарии дают 18–36
  сообщений, тариф режет до 4 / 10.
- Вложения оплачиваются в каждом ходе, пока сообщение в предыстории (до 10
  сообщений на платных тарифах) — 5 PDF по 20k символов ≈ 25k токенов на каждом
  ходе, но со второго хода в основном по цене чтения кэша.
- **Ввод прерванного ответа не списывается** (п. 1) — исправить отдельно.

## 11. Как менять

- **Цена подписки** → `PLAN_PRICE_RUB` (или env `PLAN_PRICE_*`); пересчитать
  нетто и бюджеты в `PLAN_LIMITS`.
- **Бюджет тарифа** → аргумент `_plan_quotas(...)` в `PLAN_LIMITS`.
- **Модель режима или тира** → `MODES`; новая модель — сначала строка с ценой в
  `MODELS` (все четыре: ввод, вывод, чтение кэша, запись в кэш), иначе не
  поднимется (`billing.E001`, `billing.E011`).
- **Шаг обрезки предыстории** → `CONTEXT_TRIM_STEP` (больше шаг — реже промахи
  кэша, но в среднем короче окно).
- **Как часто извлекать память** → `_EXTRACT_EVERY_REPLIES` в
  `apps/memory/services.py` (окно экстрактора следует за ним).
- **Доли режимов** → `_MODE_SHARES` (сумма = 1, `billing.E004`).
- **Длина окон** → `QUOTA_WINDOWS`; **доля 5ч-окна** → `BURST_SHARE_OF_WEEK` или
  `burst_share=` у тарифа.
- **Grace-ответы** → `DEGRADE_REQUESTS`.
- Ошибки каталога ловит `apps/billing/checks.py` на `manage.py check` / `migrate`
  (в проде `migrate` идёт до gunicorn — кривой каталог не даст контейнеру
  подняться): модель без цены (E001), `DEFAULT_PRICE` ниже потолка (W001),
  неизвестный провайдер (E002), режим забыт в словаре (E003/W002), доли ≠ 1
  (E004), тиры UI ≠ `TIERS` (E005/E006), тарифа нет в `PLAN_LIMITS` /
  `PLAN_PRICE_RUB` (E007/E008), нет флага `allow_thinking` (E009), цена триала ≠ 0
  (E010), цены кэша не в порядке `0 < чтение ≤ ввод ≤ запись` (E011), веб-поиск
  при нулевой квоте «Исследовать» (W003).
- После правки — обновить этот файл и, если меняется видимое пользователю,
  тексты тарифов в `frontend/mentorlm/src/content/billing.ts` и `landing.ts`.
